**Χρωματιστή ένδειξη κατάστασης** η σημασία του χρώματος στην αρχή κάθε γραμμής στις *Συσκευές Array* είναι η εξής:

<i class='fa fa-circle orb green-orb'></i>Κανονική λειτουργία, η συσκευή είναι ενεργή.

<i class='fa fa-circle orb grey-orb'></i>Η συσκευή είναι σε αναμονή (spun-down).

<i class='fa fa-warning orb yellow-orb'></i>Το περιεχόμενο της συσκευής εξομοιώνεται.

<i class='fa fa-times orb red-orb'></i>Η συσκευή είναι απενεργοποιημένη, το περιεχόμενο εξομοιώνεται.

<i class='fa fa-square orb blue-orb'></i>Νέα συσκευή.

<i class='fa fa-square orb grey-orb'></i>Δεν υπάρχει συσκευή, η θέση είναι κενή.

**Ταυτοποίηση** είναι η *υπογραφή* που ταυτοποιεί μοναδικά μια συσκευή αποθήκευσης. Η υπογραφή
περιλαμβάνει το μοντέλο, τον σειριακό αριθμό, το linux device id και το μέγεθος της συσκευής.

**Θερμ.** (θερμοκρασία) διαβάζεται απευθείας από τη συσκευή. Ρυθμίζετε τις μονάδες στη
σελίδα [Προτιμήσεις εμφάνισης](Settings/DisplaySettings). Δεν διαβάζουμε τη θερμοκρασία σκληρών δίσκων σε spin-down,
καθώς συνήθως αυτό τους κάνει να ξεκινήσουν· αντί γι' αυτό εμφανίζουμε το σύμβολο `*`. Εμφανίζουμε επίσης
το σύμβολο `*` για συσκευές SSD και Flash, αν και μερικές φορές αυτές οι συσκευές αναφέρουν έγκυρη
θερμοκρασία και μερικές φορές επιστρέφουν την τιμή `0`.

**Μέγεθος, Σε χρήση, Ελεύθερο** αναφέρει το συνολικό μέγεθος της συσκευής, τον χρησιμοποιούμενο και τον υπόλοιπο χώρο για αρχεία. Αυτές
οι μονάδες ρυθμίζονται επίσης στη σελίδα [Προτιμήσεις εμφάνισης](Settings/DisplaySettings). Ο
χρησιμοποιούμενος χώρος δεν θα είναι μηδέν ακόμα και σε κενό δίσκο, λόγω της επιβάρυνσης του συστήματος αρχείων.

*ΣΗΜΕΙΩΣΗ: για cache pool πολλών συσκευών, αυτά τα δεδομένα αφορούν ολόκληρο το pool, όπως επιστρέφονται από το btrfs.*

**Αναγνώσεις, Εγγραφές** είναι το πλήθος των αιτημάτων I/O που στάλθηκαν στους drivers I/O της συσκευής. Αυτά τα στατιστικά
μπορούν να μηδενιστούν οποτεδήποτε, δείτε την ενότητα Κατάσταση Array παρακάτω.

**Σφάλματα** μετρά τα σφάλματα *που δεν μπορούν να ανακτηθούν* και αναφέρθηκαν από τους drivers I/O
της συσκευής. Τα δεδομένα που λείπουν λόγω μη ανακτήσιμων σφαλμάτων ανάγνωσης του array συμπληρώνονται άμεσα μέσω ανακατασκευής
από το parity (και προσπαθούμε να γράψουμε αυτά τα δεδομένα πίσω στον τομέα ή στους τομείς που απέτυχαν). Οποιοδήποτε μη ανακτήσιμο
σφάλμα εγγραφής οδηγεί σε *απενεργοποίηση* του δίσκου.

**FS** δείχνει το σύστημα αρχείων που εντοπίστηκε στο διαμέρισμα 1 της συσκευής.

Η στήλη **Προβολή** περιέχει εικονίδιο φακέλου που δείχνει ότι η συσκευή είναι *προσαρτημένη*. Κάντε κλικ στο εικονίδιο για
περιήγηση στο σύστημα αρχείων.

Αν είναι ενεργή η επιλογή "Εμφάνιση συνόλων array" στη σελίδα [Προτιμήσεις εμφάνισης](Settings/DisplaySettings),
προστίθεται γραμμή **Σύνολο** με το άθροισμα των στατιστικών των συσκευών, συμπεριλαμβανομένης της μέσης θερμοκρασίας
των συσκευών σας.

Το Array πρέπει να είναι σε Διακοπή για να αλλάξετε τις αντιστοιχίσεις συσκευών του Array.

Ένα unRAID array αποτελείται από έναν ή δύο δίσκους Parity και έναν αριθμό δίσκων Δεδομένων. Οι δίσκοι
Δεδομένων χρησιμοποιούνται αποκλειστικά για αποθήκευση δεδομένων χρήστη, ενώ οι δίσκοι Parity παρέχουν τον πλεονασμό που απαιτείται
για ανάκαμψη από βλάβες δίσκων.

Επειδή τα δεδομένα δεν διαμοιράζονται (striping) στο array, οι δίσκοι Parity πρέπει να είναι ίσοι ή μεγαλύτεροι από τον μεγαλύτερο δίσκο
Δεδομένων. Το Parity πρέπει επίσης να είναι ο ταχύτερος δίσκος σας.

Κάθε δίσκος Δεδομένων έχει το δικό του σύστημα αρχείων και μπορεί να εξαχθεί ως
ξεχωριστό share.

Κάντε κλικ στο όνομα της Συσκευής για να ρυθμίσετε τη συσκευή και να εκτελέσετε ορισμένα βοηθητικά εργαλεία.
:end

**Χρωματιστή ένδειξη κατάστασης** η σημασία του χρώματος στην αρχή κάθε γραμμής στις *Συσκευές Pool* είναι η εξής:

<i class='fa fa-circle orb green-orb'></i>Κανονική λειτουργία, η συσκευή είναι ενεργή.

<i class='fa fa-circle orb grey-orb'></i>Η συσκευή είναι σε αναμονή (spun-down).

<i class='fa fa-square orb blue-orb'></i>Νέα συσκευή.

<i class='fa fa-square orb grey-orb'></i>Δεν υπάρχει συσκευή, η θέση είναι κενή.

**Συσκευές Pool** είναι μια μεμονωμένη συσκευή ή ένα pool πολλών συσκευών, *εκτός* του unRAID array. Μπορεί να εξαχθεί για πρόσβαση μέσω δικτύου
όπως μια συσκευή Array. Επειδή βρίσκεται εκτός του unRAID array, η εγγραφή είναι σημαντικά ταχύτερη.

Υπάρχουν δύο τρόποι ρύθμισης των συσκευών Pool:

1. Ως μεμονωμένη συσκευή, ή
2. Ως pool πολλών συσκευών.

Όταν ρυθμιστεί ως μεμονωμένη συσκευή, μπορείτε να τη διαμορφώσετε με οποιοδήποτε υποστηριζόμενο σύστημα αρχείων (btrfs, reiserfs
ή xfs). Αυτή η διαμόρφωση προσφέρει την υψηλότερη απόδοση, αλλά χωρίς καμία προστασία δεδομένων - αν η
μεμονωμένη συσκευή pool χαλάσει, όλα τα δεδομένα της μπορεί να χαθούν.

Όταν ρυθμιστεί ως pool πολλών συσκευών, το Unraid OS επιλέγει αυτόματα μορφή *btrfs-raid1* (τόσο για δεδομένα
όσο και για meta-data). Το btrfs επιτρέπει την προσθήκη οποιουδήποτε αριθμού συσκευών στο pool και κάθε αντίγραφο δεδομένων εγγυημένα
γράφεται σε δύο διαφορετικές συσκευές. Έτσι το pool αντέχει βλάβη ενός δίσκου χωρίς απώλεια δεδομένων.

Όταν τα [User Shares](/Settings/ShareSettings) είναι ενεργά, μπορούν να ρυθμιστούν ώστε να
χρησιμοποιούν αυτόματα τη συσκευή Pool για
ταχύτερες εγγραφές. Μια ειδική διεργασία παρασκηνίου, ο *mover*, μπορεί να προγραμματιστεί να εκτελείται
περιοδικά για να μεταφέρει τα αρχεία των user shares από την Cache στο Array.
:end

:array_devices_help:
#### Αντιστοίχιση συσκευών

Ένα unRAID disk array αποτελείται από έναν αριθμό δίσκων Δεδομένων και έως δύο δίσκους Parity. Οι δίσκοι
δεδομένων χρησιμοποιούνται αποκλειστικά για αποθήκευση δεδομένων χρήστη, ενώ οι δίσκοι Parity παρέχουν τον πλεονασμό που απαιτείται
για ανάκαμψη από βλάβη ενός ή δύο δίσκων.

Σημειώστε ότι χρησιμοποιούμε προσεκτικά τον όρο *δίσκος* (disk) όταν αναφερόμαστε σε συσκευή αποθήκευσης του array. Χρησιμοποιούμε
τον όρο *σκληρός δίσκος* (hard drive ή απλώς *drive*) όταν αναφερόμαστε σε πραγματική συσκευή σκληρού δίσκου (HDD).
Αυτό γιατί σε ένα σύστημα RAID είναι δυνατό να διαβάζετε/γράφετε σε έναν δίσκο του array του οποίου ο αντίστοιχος
σκληρός δίσκος είναι απενεργοποιημένος ή ακόμα και λείπει! Επιπλέον, είναι χρήσιμο να μπορούμε να ρωτήσουμε "ποια συσκευή
έχει οριστεί ως δίσκος Parity;" ή "ποια συσκευή αντιστοιχεί στο disk2;".

Χρειαζόμαστε λοιπόν έναν τρόπο να αντιστοιχίζουμε σκληρούς δίσκους σε δίσκους του array. Αυτό γίνεται εδώ, στη
σελίδα Κύρια, όταν το array είναι σε διακοπή. Για κάθε δίσκο του array υπάρχει μια αναπτυσσόμενη λίστα με όλες τις
μη αντιστοιχισμένες συσκευές. Για να αντιστοιχίσετε μια συσκευή, απλώς επιλέξτε τη από τη λίστα. Κάθε φορά που γίνεται
αντιστοίχιση, το σύστημα ενημερώνει ένα αρχείο ρυθμίσεων για να την καταγράψει.

#### Απαιτήσεις

Σε αντίθεση με τα παραδοσιακά συστήματα RAID που διαμοιράζουν (striping) τα δεδομένα σε όλες τις συσκευές του array, ένας διακομιστής Unraid
αποθηκεύει τα αρχεία σε μεμονωμένους σκληρούς δίσκους. Συνεπώς, κάθε εγγραφή αρχείου αφορά τόσο τον
δίσκο Δεδομένων όπου γράφεται το αρχείο όσο και τους δίσκους Parity. Για αυτούς τους λόγους,

* ο δίσκος Parity πρέπει να είναι ίσος ή μεγαλύτερος από οποιονδήποτε δίσκο Δεδομένων,

και

* αν υπάρχει επιλογή, οι δίσκοι Parity πρέπει να είναι οι ταχύτεροι δίσκοι σας.

#### Οδηγίες

Αυτά είναι τα βήματα που πρέπει να ακολουθήσετε όταν σχεδιάζετε το unRAID disk array σας:

1. Αποφασίστε ποιον σκληρό δίσκο θα χρησιμοποιήσετε για parity και ποιους για
δίσκους Δεδομένων disk1, disk2 κ.λπ., και σημαδέψτε τους με κάποιον τρόπο. Επίσης, βρείτε τον σειριακό αριθμό κάθε σκληρού
δίσκου και σημειώστε τον κάπου· θα χρειαστείτε αυτή την πληροφορία αργότερα.

2. Εγκαταστήστε τους σκληρούς δίσκους, εκκινήστε τον διακομιστή και ανοίξτε το webGUI. Αν πρόκειται για νέο σύστημα,
η σελίδα Κύρια δεν θα δείχνει εγκατεστημένους δίσκους. Αυτό δεν σημαίνει ότι το σύστημα δεν εντοπίζει τους
σκληρούς δίσκους σας· σημαίνει απλώς ότι δεν έχει αντιστοιχιστεί ακόμα κανένας.

3. Θυμάστε τους σειριακούς αριθμούς που σημειώσατε στο βήμα 1; Για το parity και για κάθε δίσκο Δεδομένων, επιλέξτε τον
σωστό σκληρό δίσκο από την αναπτυσσόμενη λίστα με βάση τον σειριακό του αριθμό.

#### Hot Plug

Μπορείτε επίσης να συνδέσετε σκληρούς δίσκους *εν λειτουργία* (hot plug), αν το υλικό σας το υποστηρίζει. Για παράδειγμα,
αν χρησιμοποιείτε θήκες σκληρών δίσκων, μπορείτε απλώς να τους συνδέσετε στον διακομιστή ενώ είναι αναμμένος και
το array σε Διακοπή. Ανανεώστε τη σελίδα Κύρια για να εμφανιστούν οι νέες μη αντιστοιχισμένες συσκευές στις
αναπτυσσόμενες λίστες αντιστοίχισης.

#### Επόμενα βήματα

Αφού αντιστοιχίσετε όλους τους σκληρούς δίσκους, δείτε την ενότητα Κατάσταση Array παρακάτω
και ξεκινήστε το array.
:end

:encryption_help:
#### Είσοδος κρυπτογράφησης

Με το array σε Διακοπή, ο χρήστης μπορεί να ορίσει νέο κλειδί κρυπτογράφησης. Σημειώστε ότι μόλις μια συσκευή
διαμορφωθεί με συγκεκριμένο κλειδί, μπορεί να ανοιχτεί μόνο με το ίδιο κλειδί. Η αλλαγή του κλειδιού κρυπτογράφησης απαιτεί
επαναδιαμόρφωση των κρυπτογραφημένων συσκευών, **με αποτέλεσμα τη μόνιμη απώλεια όλων των υπαρχόντων δεδομένων τους.**

#### Φράση πρόσβασης

Εισαγάγετε φράση πρόσβασης έως 512 χαρακτήρες. Συνιστάται έντονα να χρησιμοποιείτε μόνο τους 95 εκτυπώσιμους χαρακτήρες από
τους πρώτους 128 χαρακτήρες του [πίνακα ASCII](https://en.wikipedia.org/wiki/ASCII), καθώς έχουν πάντα την ίδια δυαδική
αναπαράσταση. Άλλοι χαρακτήρες μπορεί να έχουν διαφορετική κωδικοποίηση ανάλογα με τη διαμόρφωση του συστήματος και η φράση σας
δεν θα λειτουργεί με διαφορετική κωδικοποίηση. Αν θέλετε μεγαλύτερη φράση ή δυαδικά δεδομένα, ανεβάστε αρχείο κλειδιού.

Δείτε το [cryptsetup FAQ](https://gitlab.com/cryptsetup/cryptsetup/wikis/FrequentlyAskedQuestions#5-security-aspects)
για το τι θεωρείται *ασφαλής* φράση πρόσβασης.

**Απομνημονεύστε** αυτή τη φράση. **ΑΝ ΧΑΘΕΙ, ΤΟ ΚΡΥΠΤΟΓΡΑΦΗΜΕΝΟ ΠΕΡΙΕΧΟΜΕΝΟ ΔΕΝ ΜΠΟΡΕΙ ΝΑ ΑΝΑΚΤΗΘΕΙ!**

#### Αρχείο κλειδιού

Επιλέξτε τοπικό αρχείο κλειδιού με αποθηκευμένο κλειδί κρυπτογράφησης ή δυαδικό αρχείο. Το μέγιστο μέγεθος του αρχείου κλειδιού είναι 8M (8388608 byte).

Κρατήστε **αντίγραφο** του τοπικού αρχείου κλειδιού. **ΑΝ ΧΑΘΕΙ, ΤΟ ΚΡΥΠΤΟΓΡΑΦΗΜΕΝΟ ΠΕΡΙΕΧΟΜΕΝΟ ΔΕΝ ΜΠΟΡΕΙ ΝΑ ΑΝΑΚΤΗΘΕΙ!**
:end

:info_btrfs_balance_help:
Το **Balance** εκτελεί το πρόγραμμα *btrfs balance* για ανακατανομή των extents σε όλες τις συσκευές του pool, για παράδειγμα
για μετατροπή του pool από raid1 σε raid0 ή αντίστροφα.

Όταν εκτελείται *πλήρες balance*, ουσιαστικά ξαναγράφονται τα πάντα στο τρέχον σύστημα αρχείων.

Η *μετατροπή λειτουργίας* επηρεάζει τα data extents του btrfs· τα metadata χρησιμοποιούν πάντα raid1 και μετατρέπονται σε raid1, αν χρειάζεται, από οποιαδήποτε λειτουργία balance.

Ο χρόνος εκτέλεσης μπορεί να είναι πολύ μεγάλος, ανάλογα με το μέγεθος του συστήματος αρχείων και την ταχύτητα της συσκευής.

Το Unraid OS χρησιμοποιεί αυτές τις προεπιλεγμένες επιλογές κατά τη δημιουργία pool πολλών συσκευών:

`-dconvert=raid1 -mconvert=raid1`

Για πληρέστερη τεκμηρίωση, δείτε το [Manpage](https://man7.org/linux/man-pages/man8/btrfs-balance.8.html) του btrfs-balance

*ΣΗΜΕΙΩΣΗ: τα raid5 και raid6 θεωρούνται γενικά ακόμα **πειραματικά** από την κοινότητα του Linux*
:end

:info_balance_cancel_help:

:end

:info_btrfs_scrub_help:
Το **Scrub** εκτελεί το πρόγραμμα *btrfs scrub*, το οποίο διαβάζει όλα τα μπλοκ δεδομένων και metadata από όλες τις
συσκευές και επαληθεύει τα checksums.

Το *btrfs scrub* θα επιδιορθώσει τα αλλοιωμένα μπλοκ αν υπάρχει διαθέσιμο σωστό αντίγραφο.

Όταν πρέπει να δημιουργηθεί νέο αρχείο ή υποφάκελος σε ένα share, το Unraid OS επιλέγει πρώτα σε ποιον δίσκο
θα δημιουργηθεί, σύμφωνα με τη ρυθμισμένη *Μέθοδο κατανομής*. Αν ο γονικός φάκελος που περιέχει
το νέο αρχείο ή υποφάκελο δεν υπάρχει σε αυτόν τον δίσκο, το Unraid OS δημιουργεί πρώτα όλους τους απαραίτητους
γονικούς φακέλους και μετά το νέο αρχείο ή υποφάκελο.

**Αυτόματος διαχωρισμός μόνο του πρώτου επιπέδου φακέλων όπως απαιτείται**
Όταν δημιουργείται νέο αρχείο ή υποφάκελος στον υποφάκελο πρώτου επιπέδου ενός share και αυτός ο υποφάκελος
πρώτου επιπέδου δεν υπάρχει στον δίσκο όπου γίνεται η εγγραφή, ο υποφάκελος δημιουργείται πρώτα.
Αν δημιουργείται νέο αρχείο ή υποφάκελος σε υποφάκελο δεύτερου ή χαμηλότερου επιπέδου, το νέο
αρχείο ή υποφάκελος δημιουργείται στον ίδιο δίσκο με τον γονικό του φάκελο.

**Αυτόματος διαχωρισμός μόνο των πρώτων "N" επιπέδων φακέλων όπως απαιτείται**
Παρόμοιο με το προηγούμενο: όταν δημιουργείται νέο αρχείο ή υποφάκελος και ο γονικός φάκελος είναι στο επίπεδο "N"
και δεν υπάρχει στον επιλεγμένο δίσκο, το Unraid OS δημιουργεί πρώτα όλους τους απαραίτητους γονικούς φακέλους. Αν ο
γονικός φάκελος του νέου αρχείου ή υποφακέλου βρίσκεται πέρα από το επίπεδο "N", το νέο αρχείο ή υποφάκελος
δημιουργείται στον ίδιο δίσκο όπου υπάρχει ο γονικός φάκελος.

**Χειροκίνητα: χωρίς αυτόματο διαχωρισμό φακέλων**
Όταν πρέπει να δημιουργηθεί νέο αρχείο ή υποφάκελος σε ένα share, το Unraid OS λαμβάνει υπόψη μόνο τους δίσκους όπου
ο γονικός φάκελος υπάρχει ήδη.
:end

:share_edit_cache_pool_help:
Ορίστε αν τα νέα αρχεία και οι φάκελοι που γράφονται στο share μπορούν να γράφονται στον δίσκο/pool Cache, αν υπάρχει.
Η ρύθμιση επηρεάζει επίσης τη συμπεριφορά του *mover*.

Το **Όχι** απαγορεύει την εγγραφή νέων αρχείων και υποφακέλων στον δίσκο/pool Cache.
Ο *Mover* δεν κάνει καμία ενέργεια, οπότε τα υπάρχοντα αρχεία αυτού του share που βρίσκονται στην cache παραμένουν εκεί.

Το **Ναι** σημαίνει ότι όλα τα νέα αρχεία και υποφάκελοι πρέπει να γράφονται στον δίσκο/pool Cache, εφόσον
υπάρχει αρκετός ελεύθερος χώρος σε αυτόν.
Αν δεν υπάρχει αρκετός χώρος στον δίσκο/pool Cache, τα νέα αρχεία και οι φάκελοι δημιουργούνται στο array.
Όταν εκτελείται ο *mover*, τα αρχεία και οι υποφάκελοι μεταφέρονται από τον δίσκο/pool Cache στο array.

Το **Μόνο** σημαίνει ότι όλα τα νέα αρχεία και υποφάκελοι πρέπει υποχρεωτικά να γράφονται στον δίσκο/pool Cache.
Αν δεν υπάρχει αρκετός ελεύθερος χώρος στον δίσκο/pool Cache, οι λειτουργίες *δημιουργίας* θα αποτυγχάνουν με κατάσταση *out of space*.
Ο *Mover* δεν κάνει καμία ενέργεια, οπότε τα υπάρχοντα αρχεία αυτού του share που βρίσκονται στο array παραμένουν εκεί.

Το **Προτίμηση** σημαίνει ότι όλα τα νέα αρχεία και υποφάκελοι πρέπει να γράφονται στον δίσκο/pool Cache, εφόσον
υπάρχει αρκετός ελεύθερος χώρος σε αυτόν.
Αν δεν υπάρχει αρκετός χώρος στον δίσκο/pool Cache, τα νέα αρχεία και οι φάκελοι δημιουργούνται στο array.
Όταν εκτελείται ο *mover*, τα αρχεία και οι υποφάκελοι μεταφέρονται από το array στον δίσκο/pool Cache.

**ΣΗΜΕΙΩΣΗ:** Ο Mover δεν μετακινεί ποτέ αρχεία που χρησιμοποιούνται εκείνη τη στιγμή.
Αυτό σημαίνει ότι αν θέλετε να μετακινήσετε αρχεία που σχετίζονται με υπηρεσίες συστήματος όπως Docker ή VMs, πρέπει να
απενεργοποιήσετε αυτές τις υπηρεσίες όσο εκτελείται ο mover.
:end

:smb_case_sensitive_names_help:
Ελέγχει αν τα ονόματα αρχείων κάνουν διάκριση πεζών-κεφαλαίων.

Η προεπιλογή **auto** επιτρέπει στους clients που υποστηρίζουν ονόματα με διάκριση πεζών-κεφαλαίων (Linux CIFSVFS)
να δηλώνουν στον διακομιστή Samba ανά πακέτο ότι θέλουν πρόσβαση με διάκριση πεζών-κεφαλαίων (για υποστήριξη της
σημασιολογίας του UNIX). Κανένα σύστημα Windows δεν υποστηρίζει διάκριση πεζών-κεφαλαίων, οπότε για αυτά η ρύθμιση **auto** είναι
ίδια με το Όχι· ωστόσο, διατηρείται η γραφή των ονομάτων που στέλνει ένας client Windows. Η ρύθμιση μπορεί να μειώσει
την απόδοση σε πολύ μεγάλους φακέλους, επειδή το Samba πρέπει να κάνει αναζήτηση και αντιστοίχιση των ονομάτων.

Η ρύθμιση **Ναι** σημαίνει ότι τα αρχεία δημιουργούνται με τη γραφή που στέλνει ο client και είναι προσβάσιμα μόνο με την ίδια γραφή.
Αυτό επιταχύνει την πρόσβαση σε πολύ μεγάλους φακέλους, αλλά ορισμένες εφαρμογές Windows μπορεί να μη λειτουργούν σωστά. Για

Η τιμή **Μόνο πεζά** είναι ειδική: όλα τα εισερχόμενα ονόματα αρχείων από clients, όχι μόνο τα νέα, μετατρέπονται σε πεζά.
Με άλλα λόγια, όποια μικτή γραφή κι αν δημιουργηθεί στα Windows, το όνομα αποθηκεύεται και προσπελάζεται μόνο με πεζά. Έτσι
όλες οι εφαρμογές Windows βρίσκουν σωστά κάθε αρχείο ανεξαρτήτως γραφής, αλλά η γραφή δεν διατηρείται στις λίστες φακέλων.
ΣΗΜΕΙΩΣΗ: αυτή η ρύθμιση πρέπει να ορίζεται μόνο για νέα shares.

υποστήριξη των λεγόμενων δίσκων *Advanced Format*.

:mgmt_use_ssl_tls_help:
Καθορίζει πώς αποκρίνεται το webGUI στα πρωτόκολλα HTTP ή/και HTTPS στο LAN σας.

Επιλέξτε **Όχι** για χρήση HTTP. Για πρόσβαση στον διακομιστή σας χρησιμοποιήστε αυτό το URL:

`http://<server-name>.<localTLD>`

ή αυτό το URL:

`http://<server-ip-address>`

Επιλέξτε **Ναι** για χρήση αυτόματα δημιουργημένου αυτο-υπογεγραμμένου
πιστοποιητικού SSL. Χρησιμοποιήστε αυτό το URL για πρόσβαση στον διακομιστή σας:

`https://<server-name>.<localTLD>`

Σημειώστε ότι η χρήση αυτο-υπογεγραμμένου πιστοποιητικού SSL προκαλεί προειδοποίηση
στον browser.

Επιλέξτε **Strict** για *αποκλειστική* χρήση πιστοποιητικού SSL myunraid.net
για πρόσβαση https (δείτε **Έκδοση** παρακάτω). Σημειώστε ότι πρέπει να είναι
προσβάσιμος κάποιος διακομιστής DNS.

**Ανακατευθύνσεις:** Κατά την πρόσβαση στο `http://<server-ip-address>` ή στο `http://<server-name>.<localTLD>`, η
συμπεριφορά αλλάζει ανάλογα με την τιμή της ρύθμισης Χρήση SSL/TLS:

* Αν η Χρήση SSL/TLS είναι **Strict**, θα ανακατευθυνθείτε στο `https://<lan-ip>.<hash>.myunraid.net`
* Αν η Χρήση SSL/TLS είναι **Ναι**, θα ανακατευθυνθείτε στο `https://<server-ip-address> or https://<server-name>.<localTLD>`
* Αν η Χρήση SSL/TLS είναι **Όχι**, το http url φορτώνει απευθείας.

Σημαντικό: Το **Strict** μπορεί να μην είναι διαθέσιμο αν ο router ή ο upstream διακομιστής DNS σας έχει ενεργή
[προστασία DNS rebinding](https://en.wikipedia.org/wiki/DNS_rebinding). Η προστασία DNS rebinding
εμποδίζει το DNS να επιλύει ιδιωτικά εύρη IP. Πρόκειται για λειτουργία ασφαλείας
σε LAN που μπορεί να περιλαμβάνει παλιές συσκευές με προβληματικές/μη ασφαλείς "web" διεπαφές.

Μία πηγή προστασίας DNS rebinding μπορεί να είναι ο διακομιστής DNS του παρόχου σας. Σε αυτή την περίπτωση το πρόβλημα λύνεται
αλλάζοντας σε άλλο διακομιστή DNS, όπως το OpenDNS, όπου η προστασία DNS rebinding μπορεί να απενεργοποιηθεί.

Συνηθέστερα, η προστασία DNS rebinding μπορεί να είναι ενεργή στον router σας. Οι περισσότεροι οικιακοί routers δεν υλοποιούν προστασία DNS
rebinding· αν όμως την υλοποιούν, θα υπάρχει ρύθμιση για απενεργοποίησή της.

Οι routers υψηλότερης κατηγορίας συνήθως έχουν ενεργή την προστασία DNS rebinding. Συνήθως υπάρχουν τρόποι να απενεργοποιηθεί
εντελώς ή επιλεκτικά ανά domain. Παραδείγματα:

**DD-WRT:** Αν χρησιμοποιείτε "dnsmasq" με ενεργή προστασία DNS rebinding, μπορείτε να προσθέσετε αυτή τη γραμμή στο αρχείο
ρυθμίσεων του router:

`rebind-domain-ok=/myunraid.net/`

**pfSense:** Αν χρησιμοποιείτε την εσωτερική υπηρεσία DNS resolver του pfSense, μπορείτε να προσθέσετε αυτές τις γραμμές Custom Option:

`server:`<br>
`private-domain: "myunraid.net"`

**Ubiquiti USG router:** μπορείτε να προσθέσετε αυτή τη γραμμή ρυθμίσεων:

`set service dns forwarding options rebind-domain-ok=/myunraid.net/`

**OpenDNS:** Μεταβείτε στο Settings -> Security και *αφαιρέστε* το σημάδι από το
 "Suspicious Responses - Block internal IP addresses". Είναι ρύθμιση όλα-ή-τίποτα.

Αν όλα τα άλλα αποτύχουν, μπορείτε να δημιουργήσετε μια εγγραφή στο αρχείο *hosts* του υπολογιστή σας ώστε να παρακάμψετε το εξωτερικό DNS και
να επιλύεται απευθείας το myunraid.net FQDN του διακομιστή σας στην τοπική του διεύθυνση IP.
:end

:mgmt_certificate_expiration_help:
Η **Έκδοση** μπορεί να χρησιμοποιηθεί για εγκατάσταση *δωρεάν* πιστοποιητικού SSL myunraid.net από το
[Let’s Encrypt](https://letsencrypt.org/).

Το πιστοποιητικό SSL myunraid.net μπορεί να χρησιμοποιηθεί με δύο τρόπους. Πρώτον,
η ύπαρξη του πιστοποιητικού επιτρέπει στον διακομιστή σας να αποκρίνεται σε ένα
εναλλακτικό URL της μορφής:

`https://<lan-ip>.<hash>.myunraid.net`

Η τιμή `<hash>` είναι μια δεκαεξαδική συμβολοσειρά 40 χαρακτήρων (160 bits), μοναδική για
τον διακομιστή σας. Ένας διακομιστής DDNS της Lime Technology επιστρέφει το `<lan-ip>` σας
ως απάντηση σε αίτημα DNS για αυτό το URL. Το Subject του πιστοποιητικού
ορίζεται σε `*.<hash>.myunraid.net`, επικυρώνοντας έτσι τη σύνδεση https.

Μπορείτε να ενεργοποιήσετε αποκλειστικά αυτό το URL στο LAN σας ορίζοντας τη **Χρήση
SSL/TLS** σε **Strict**.

Η δεύτερη χρήση του πιστοποιητικού myunraid.net είναι η ενεργοποίηση ασφαλούς
απομακρυσμένης πρόσβασης μέσω της λειτουργίας του plugin Unraid Connect. Σημειώστε
ότι μπορείτε να χρησιμοποιείτε ασφαλή απομακρυσμένη πρόσβαση μαζί με
μη ασφαλή τοπική πρόσβαση.

Αφού εγκατασταθεί πιστοποιητικό SSL myunraid.net, ενεργοποιείται μια
υπηρεσία παρασκηνίου:

- *renewcert* - Ξεκινά 60 δευτερόλεπτα μετά την ολοκλήρωση της επανεκκίνησης του διακομιστή και επικοινωνεί με την υπηρεσία
ανανέωσης πιστοποιητικών της Lime Technology για να διαπιστώσει αν το πιστοποιητικό SSL myunraid.net σας χρειάζεται ανανέωση.
Στη συνέχεια ενεργοποιείται κάθε 24 ώρες. Αν απομένουν έως 30 ημέρες μέχρι τη λήξη, εκδίδεται αυτόματα νέο πιστοποιητικό
και κατεβαίνει στον διακομιστή σας.

Η **Διαγραφή** μπορεί να χρησιμοποιηθεί για διαγραφή του αρχείου πιστοποιητικού myunraid.net.

**Λεπτομέρειες διαχείρισης πιστοποιητικών nginx**

Το nginx χρησιμοποιεί δύο αρχεία πιστοποιητικών αποθηκευμένα στη συσκευή εκκίνησης USB flash:<br>

- ένα αυτο-υπογεγραμμένο πιστοποιητικό: `config/ssl/certs/<server-name>_unraid_bundle.pem`

- ένα πιστοποιητικό myunraid.net: `config/ssl/certs/certificate_bundle.pem`

Το αρχείο αυτο-υπογεγραμμένου πιστοποιητικού SSL δημιουργείται αυτόματα όταν ξεκινά το nginx
και δημιουργείται ξανά αν αλλάξει το hostname ή το τοπικό TLD του διακομιστή.

**Υποστήριξη stapling του nginx**

Το OCSP Stapling ενεργοποιείται αυτόματα αν το πιστοποιητικό περιέχει URL OCSP responder.

Επομένως, για αυτο-υπογεγραμμένα πιστοποιητικά το stapling δεν ενεργοποιείται· για πιστοποιητικά υπογεγραμμένα από CA
το stapling ενεργοποιείται.
:end

:nfs_tunable_fuse_remember_help:
Όταν το NFS είναι ενεργό, αυτό το Tunable μπορεί να χρησιμοποιηθεί για να μετριάσει ή να λύσει περιπτώσεις "NFS Stale File Handles"
που ίσως συναντήσετε με τον NFS client σας.

Ουσιαστικά, το (fuse_remember) λέει σε ένα εσωτερικό υποσύστημα (με όνομα "fuse") πόσο χρόνο να "θυμάται" ή να "κρατά στην cache"
τις πληροφορίες αρχείων και φακέλων των user shares. Όταν ένας NFS client προσπαθεί να προσπελάσει ένα αρχείο
(ή φάκελο) στον διακομιστή και το όνομα αυτού του αρχείου (ή φακέλου) δεν είναι στην cache, μπορεί να εμφανιστεί
"stale file handle".

Η αριθμητική τιμή αυτού του tunable είναι ο αριθμός δευτερολέπτων που διατηρούνται στην cache τα ονόματα αρχείων/φακέλων,
όπου η προεπιλεγμένη τιμή 330 αντιστοιχεί σε 5 1/2 λεπτά. Υπάρχουν επίσης δύο ειδικές τιμές που μπορείτε
να ορίσετε:

* 0, που σημαίνει να μη διατηρούνται καθόλου στην cache ονόματα αρχείων/φακέλων, και
* -1, που σημαίνει να διατηρούνται για πάντα (ή μέχρι να σταματήσει το array)

Η τιμή 0 είναι κατάλληλη αν ενεργοποιείτε το NFS αλλά σκοπεύετε να το χρησιμοποιείτε μόνο για disk shares,
όχι για user shares.

Η τιμή -1 είναι κατάλληλη αν καμία άλλη τιμή δεν φαίνεται να λύνει το "stale file handle" στον
client σας. Λάβετε υπόψη ότι η τιμή -1 αυξάνει τη χρήση μνήμης κατά περίπου
108 bytes ανά όνομα αρχείου/φακέλου στην cache. Ανάλογα με τη μνήμη RAM του διακομιστή σας και το πλήθος
αρχείων/φακέλων που προσπελάζετε μέσω NFS, αυτό μπορεί να οδηγήσει ή όχι σε εξάντληση μνήμης.
:end

:eth_bonding_mode_help:
**Mode 0 (balance-rr)**<br>
Αυτή η λειτουργία μεταδίδει πακέτα με διαδοχική σειρά, από το πρώτο διαθέσιμο slave έως το τελευταίο.
Αν δύο πραγματικές διεπαφές είναι slaves στο bond και φτάσουν δύο πακέτα προς έξοδο από τη bonded διεπαφή, το πρώτο θα μεταδοθεί από το πρώτο slave και το δεύτερο από το δεύτερο slave.
Το τρίτο πακέτο θα σταλεί από το πρώτο κ.ο.κ. Παρέχει εξισορρόπηση φόρτου και ανοχή σε σφάλματα.

**Mode 1 (active-backup) - προεπιλογή**<br>
Αυτή η λειτουργία θέτει μία από τις διεπαφές σε κατάσταση εφεδρείας και την ενεργοποιεί μόνο αν χαθεί η σύνδεση της ενεργής διεπαφής.
Μόνο ένα slave του bond είναι ενεργό κάθε στιγμή. Άλλο slave ενεργοποιείται μόνο όταν αποτύχει το ενεργό.
Παρέχει ανοχή σε σφάλματα.

**Mode 2 (balance-xor)**<br>
Αυτή η λειτουργία μεταδίδει πακέτα βάσει τύπου XOR. Η MAC προέλευσης γίνεται XOR με τη MAC προορισμού modulo το πλήθος των slaves.
Έτσι επιλέγεται το ίδιο slave για κάθε MAC προορισμού και παρέχεται εξισορρόπηση φόρτου και ανοχή σε σφάλματα.

**Mode 3 (broadcast)**<br>
Αυτή η λειτουργία μεταδίδει τα πάντα σε όλες τις διεπαφές slave. Χρησιμοποιείται σπάνια (μόνο για ειδικό σκοπό) και παρέχει μόνο ανοχή σε σφάλματα.

**Mode 4 (802.3ad)**<br>
Αυτή η λειτουργία είναι γνωστή ως *Dynamic Link Aggregation*. Δημιουργεί ομάδες συνάθροισης με τις ίδιες ρυθμίσεις ταχύτητας και duplex.
Απαιτεί switch που υποστηρίζει IEEE 802.3ad dynamic link.
Η επιλογή slave για την εξερχόμενη κίνηση γίνεται σύμφωνα με την πολιτική transmit hash, που μπορεί να αλλάξει από την προεπιλεγμένη απλή πολιτική XOR μέσω της επιλογής xmit_hash_policy.
Σημειώστε ότι δεν είναι όλες οι πολιτικές μετάδοσης συμβατές με το 802.3ad, ιδίως όσον αφορά τις απαιτήσεις για λάθος σειρά πακέτων της ενότητας 43.2.4 του προτύπου 802.3ad.
Διαφορετικές υλοποιήσεις peer έχουν διαφορετική ανοχή στη μη συμμόρφωση.

**Mode 5 (balance-tlb)**<br>
Αυτή η λειτουργία ονομάζεται *Adaptive transmit load balancing*. Η εξερχόμενη κίνηση κατανέμεται σύμφωνα με τον τρέχοντα φόρτο και την ουρά κάθε διεπαφής slave.
Η εισερχόμενη κίνηση λαμβάνεται από το τρέχον slave.

**Mode 6 (balance-alb)**<br>
Αυτή η λειτουργία ονομάζεται *Adaptive load balancing*. Περιλαμβάνει balance-tlb + εξισορρόπηση φόρτου λήψης (rlb) για κίνηση IPV4.
Η εξισορρόπηση φόρτου λήψης επιτυγχάνεται μέσω διαπραγμάτευσης ARP.
Ο bonding driver παρεμβαίνει στις απαντήσεις ARP που στέλνει ο διακομιστής και αντικαθιστά τη διεύθυνση υλικού προέλευσης με τη μοναδική διεύθυνση υλικού ενός από τα slaves του bond,
ώστε διαφορετικοί clients να χρησιμοποιούν διαφορετικές διευθύνσεις υλικού για τον διακομιστή.

*Το Mode 1 (active-backup) είναι η συνιστώμενη ρύθμιση. Οι άλλες λειτουργίες επιτρέπουν συγκεκριμένα σενάρια, αλλά μπορεί να απαιτούν κατάλληλη υποστήριξη από το switch.
Η επιλογή μη υποστηριζόμενης λειτουργίας μπορεί να διαταράξει την επικοινωνία.*
:end

:apc_ups_type_help:

+ **Dumb** - παλιά σειριακή συσκευή χαρακτήρων για UPS με απλή σηματοδοσία
+ **PCnet** - πρωτόκολλο PowerChute Network Shutdown, που μπορεί να χρησιμοποιηθεί αντί για SNMP με την οικογένεια καρτών smart slot AP9617
+ **ModBus** - σειριακή συσκευή για τα νεότερα μοντέλα SmartUPS που υποστηρίζουν το πρωτόκολλο MODBUS

:apc_ups_device_help:
Εισαγάγετε τη *συσκευή* που αντιστοιχεί στην περίπτωσή σας, μόνο όταν ο *Τύπος UPS* δεν είναι USB.

+ **apcsmart** - /dev/tty**
+ **net** - hostname:port. Το hostname είναι η διεύθυνση IP του διακομιστή NIS. Η προεπιλεγμένη θύρα είναι 3551
+ **snmp** - hostname:port:vendor:community. Το hostname είναι η διεύθυνση ip ή το hostname του UPS στο δίκτυο. Το vendor μπορεί να είναι "APC" ή "APC_NOTRAP". Το "APC_NOTRAP" απενεργοποιεί τη λήψη SNMP traps· συνήθως θέλετε "APC". Η θύρα είναι συνήθως 161. Το community είναι συνήθως "private"
+ **dumb** - /dev/tty**
+ **pcnet** - ipaddr:username:passphrase:port. Το ipaddr είναι η διεύθυνση IP της κάρτας διαχείρισης του UPS. Τα username και passphrase είναι τα διαπιστευτήρια με τα οποία έχει ρυθμιστεί η κάρτα. Το port είναι η θύρα όπου ακούει για μηνύματα από το UPS, συνήθως 3052. Αν η παράμετρος είναι κενή ή λείπει, χρησιμοποιείται η προεπιλογή 3052
+ **modbus** - /dev/tty**

:wg_local_endpoint_help:
Αυτό το πεδίο συμπληρώνεται αυτόματα με το δημόσιο domain name διαχείρισης *&lt;wan-ip&gt;.&lt;hash&gt;.myunraid.net* ή τη δημόσια διεύθυνση του διακομιστή.<br>
Έτσι μπορούν να δημιουργηθούν VPN tunnels από εξωτερικούς peers προς τον διακομιστή.<br>
Ρυθμίστε το σωστό port forwarding στον router σας (η προεπιλεγμένη θύρα είναι <?=$netport['wg0']?>, αλλά μπορεί να αλλάξει) ώστε οι εισερχόμενες συνδέσεις να φτάνουν στον διακομιστή.

Οι χρήστες με καταχωρισμένο domain name μπορούν να χρησιμοποιήσουν αυτό το πεδίο για να ορίσουν πώς είναι γνωστός ο διακομιστής τους στο Internet. Π.χ. www.myserver.mydomain.<br>
Και πάλι, βεβαιωθείτε ότι ο router σας είναι σωστά ρυθμισμένος.

Σημείωση για χρήστες Cloudflare: το proxy της Cloudflare έχει σχεδιαστεί για κίνηση http και δεν μπορεί να κάνει proxy κίνηση VPN. Πρέπει να απενεργοποιήσετε το proxy της Cloudflare για να χρησιμοποιήσετε VPN με το domain σας.
:end

:wg_local_server_uses_nat_help:
Όταν το NAT είναι ενεργό, ο διακομιστής χρησιμοποιεί τη δική του διεύθυνση LAN όταν προωθεί κίνηση από το tunnel προς άλλες συσκευές του LAN.
Χρησιμοποιήστε αυτή τη ρύθμιση όταν δεν θέλετε αλλαγές στον router, αλλά αυτή η προσέγγιση δεν λειτουργεί με Docker containers που χρησιμοποιούν προσαρμοσμένες διευθύνσεις IP.

Όταν το NAT είναι ανενεργό, ο διακομιστής χρησιμοποιεί τη διεύθυνση του WireGuard tunnel κατά την προώθηση κίνησης.
Σε αυτή την περίπτωση απαιτείται η προεπιλεγμένη πύλη (router) να έχει στατική διαδρομή που να παραπέμπει τη διεύθυνση του tunnel πίσω στον διακομιστή.
:end

:WOL_intro_help:
Αυτή η σελίδα επιτρέπει τη ρύθμιση εκκίνησης/συνέχισης και διακοπής VMs και Containers (Docker και LXC) μέσω πακέτων Wake-on-LAN (WOL) magic.

Δεν ρυθμίζει την αφύπνιση του ίδιου του διακομιστή Unraid.

Η διαδικασία αναζητά τη διεύθυνση MAC που ορίζεται στην υπηρεσία (VM ή Container). Εξαίρεση αποτελούν τα Dockers, που δεν έχουν διεύθυνση MAC μέχρι να εκτελεστούν. Γι' αυτό, πρέπει να ορίσετε διεύθυνση MAC από τον χρήστη για να τα ξεκινάτε.

Αν η υπηρεσία είναι σε παύση, ένα πακέτο WOL θα τη συνεχίσει.

Για κάθε υπηρεσία μπορείτε να ορίσετε: **ενεργοποίηση**, **απενεργοποίηση** ή **ενεργοποίηση και τερματισμός**.

Όταν έχει οριστεί “ενεργοποίηση και τερματισμός” και η υπηρεσία εκτελείται όταν ληφθεί το επόμενο πακέτο WOL, θα γίνει τερματισμός.
:end
